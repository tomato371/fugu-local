Premise

何が既に手に入っているか

2026-08-06 訂正 — このページの総合スコアは和集合でした

本ページに現れる 199/210 系の数値は、20 以上の構成の和集合 （どれか 1 つの構成で解けたら正解）として集計したものでした。 比較対象の基準モデル 199.5/210 は単一モデルの成績なので、性質が違います。

単一構成の最良合計は 187/210 です。公平な比較は 187 対 199.5 で、 12.5 問の差があります。「40% → 97%（+57pt）」も分子が和集合・分母が n=5 で、 正直な値は 単発 2/5 に対し sc@nim 単一構成 25/30（83%）です。

経緯と再集計の詳細は次期設計ページの冒頭にあります。 以下の本文は当時のまま残します。

ロードマップの前に、確定した事実を置きます。ここから先の計画は、すべてこの 3 点に依存しています。

ひとつ、推論能力は 0 円で調達できるようになりました。 6 種目 210 問で 199 問。同一ハーネスで測った基準モデルと事実上同点で、外部課金はゼロです。 つまり「賢さ」はもうボトルネックではありません。

ふたつ、増幅率が測れています。 同じモデル群を単発で呼べば 40%、 オーケストレーションに通せば 97%。差の 57 ポイントが設計の寄与で、モデルは同一なので交絡がありません。 この層は Fable と競合しません——モデルに掛ける係数です。 より強いモデルが手に入れば、同じ層がそれを増幅します。

みっつ、無人で 4 日間動きました。 16,506 リクエスト、11 プロセス並走、 レート制限・空応答・ハングを自動で吸収しながら。 人間が寝ている間に計算が進むという条件は、すでに満たされています。

だから次の問いは「精度」ではない

ベンチマークの点数を 199 から 205 に上げても、生活は 1 ミリも変わりません。 意味があるのは、この層を通すと何が自動化され、何が観測できるようになり、 何時間が返ってくるかのほうです。以下の 3 本はその変換装置です。

Line A · nearest

A — 常用の対話 AI（最短。ほぼ設定変更）

新規開発はほとんど要りません。会話型 AI を作ろうとして人が挫折するのは 面白くない土台の部分ですが、それは既に終わっています—— 会話履歴の永続化とプロジェクト別セッション、SSE ストリーミング、 指数バックオフとモデル別クールダウン、起動時の可用性プローブ、 CLI / TUI / Web UI / REST / MCP の 5 つの入口、そして自作の RAG。

足りないのは既定値の向きだけです。いまの Conductor は 「91 は素数ですか」を 3 モデルの合議に回します。ベンチで勝つには正しい判断ですが、 会話としては過剰です。

正直に — 雑談の質でフロンティア単体には勝てません

投票は答えが 1 つに定まる問題でしか効きません。会話にはその構造がないので、 統合役の知能が上限になります。ここで勝負しても負けます。

勝負すべき軸は別です——自分の文書を知っていて、データが外に出ず、0 円で、 人格が固定で、必要なら 30 分考えさせられる。 この組み合わせはどのフロンティア API も提供しません。 汎用の賢さではなく、自分の文脈に接続されていることが価値です。

完了条件

平易な問いの応答が中央値 10 秒以内（現在の中央値は 5.3 分）。 かつ /deep 指定時には従来どおり AIME 級の熟考に入る。 かつ既存のベンチ構成 sc@nim 〜 u@nim の挙動が 1 バイトも変わらない。

Line B · compounding

B — 自律開発（複利が効く唯一の線）

素材は揃っています。役割分担した自律改良チーム、軌跡のハーベスト基盤、 そしてこの 4 日間そのもの——理論を設計し、実装し、テストを書き、 実測し、失敗を記録して次の理論へ回す、というループを人間 1 人＋AI で 5 周しました。 これを自動化するのが B です。

ここで、この 4 日間の実測から出た制約が効いてきます。 投票・審理・検証が機能するのは、正誤が機械的に判定できる領域だけでした。 コード生成で振る舞い等価性ハッシュ（同じ入力に同じ出力を返すなら等価）が使えたのは、 実行して確かめられるからです。逆に、答えが定まらない領域では どんな集約設計も効きませんでした。

したがって自律開発が回るかどうかは、賢さではなく 「テストが書けるか」で決まります。これは設計上の制約であり、 モデルが強くなっても消えません。

最初の題材は既にある

洪水予測（外挿に強い水文モデル）は、この線の最初の題材として条件が揃っています—— 正解が観測データとして存在し、評価指標が定義でき、 微分可能物理と機械学習の組み合わせという未解決の設計空間がある。 自律ループが「テストの書ける領域でのみ回る」という制約に、そのまま適合します。

ここで回れば、同じループを別領域へ複製できます。B が複利になるのは、 成果物がコードではなくループそのものだからです。

完了条件

人間の介入なしに「仮説 → 実装 → 測定 → 棄却または採択」を 10 周し、 そのうち 1 周でも採択に到達すること。 採択の基準は事前に固定し、後から動かさない。 10 周すべてが棄却でも失敗ではありません——棄却を出せる装置であることが先で、 当てることは後です。

Line C · most dangerous

C — 資産運用の検証（3 本で最も危険）

期待を先に下げておきます。バックテストは、この世で最も自己欺瞞が起きやすい計算です。 コードは常に動き、曲線は常に右肩上がりに作れ、そして実運用では溶けます。 A や B の失敗はコストが時間だけですが、C の失敗は金銭で払わされます。

ただし——このプロジェクトには、まさにその失敗を防ぐための作法が既にあります。 自作の採点器を疑い、表記ゆれで 6 問が誤判定されていたことを見つけ、 評価を取り下げたのがこのサイトです。 同じ懐疑をバックテストに向けるなら、C は「儲ける装置」ではなく 「儲からないと判定する装置」として設計されるべきです。

既定で疑うべき 5 つ（すべて実装前に決める）

① 先読み。 決算・指数構成銘柄・調整後株価は、当時は知り得なかった情報を含みます。 「その時点で実際に取得できた値か」をデータ層で強制します。

② 生存者バイアス。 上場廃止した銘柄が欠けたデータで測ると、必ず勝ちます。

③ 過剰適合。 パラメータを 1 つ増やすたびに過去は良くなります。 探索した組み合わせの総数を記録し、それを踏まえて有意性を割り引く—— AI に探索させると人間の手作業より桁違いに多く試せるため、この線では 探索能力そのものが最大のリスク要因になります。

④ 取引コスト。 手数料・スプレッド・スリッページ・約定可能性。 これを入れた瞬間に消える戦略が大半です。

⑤ 単一の系列。 1 本の資産曲線は 1 サンプルです。 期間を分け、市場を分け、ウォークフォワードで測ります。

完了条件 — 「勝った」ではなく「棄却できた」

探索した戦略の 9 割以上を、事前に決めた基準で自動的に棄却できること。 棄却率が低い装置は、良い戦略を見つけたのではなく基準が緩いだけです。

そのうえで生き残った戦略があれば、実弾を入れる前に、 完全に未見の期間で 3 か月以上の前向き検証（ペーパートレード）を通す。 ここを飛ばした戦略には、金額の大小にかかわらず 1 円も入れない。

この線を「財力」と呼ぶのは、当てて増やすからではありません。 根拠のない戦略に金を入れずに済むこと自体が、最大の期待値改善だからです。

Kill criteria

何を見たら止めるか

このプロジェクトは、「中止を出せることが成功条件に含まれる」という作法で 運営されてきました（段別投票の改修は事前診断で中止判定を出し、それでも実装して測り、 予測と実測が一致することを確認しました）。同じ規律を 3 本にも適用します。

止めるべき兆候

  • −A: 会話プロファイルにしても中央値が 1 分を切らない → 土台の速度問題であり、設定では直らない
  • −B: 10 周して採択も棄却も出ない（判定不能ばかり） → 評価指標の設計に失敗している
  • −C: 棄却率が 5 割を下回る → 基準が緩い。戦略ではなく基準を疑う
  • −共通: 「もう少しで動きそう」が 3 週間続く → 前提が間違っている

続けてよい兆候

  • +失敗が具体的な数値で説明できている（「なんとなく駄目」ではない）
  • +同じ失敗が二度起きない仕組みが、そのつど入っている
  • +効かなかった構成が、注記つきで残されている
  • +人間の作業時間が、周を追うごとに減っている

Order

着手の順序と、その理由

A → B → C の順で進めます。 魅力の順ではなく、失敗の安さの順です。

A は最も安く（設定変更で半日）、最も早く毎日効きます。 そして A を作る過程で「この系がどこで遅く、どこで壊れるか」が身体で分かります—— それは B の自律ループを設計するための前提知識になります。

B は複利が効く唯一の線です。成果物がコードではなくループなので、 1 領域で回れば別領域へ複製できます。 そして B が回っていることは、C の探索を安全に回すための必要条件でもあります—— 自動で棄却できる装置を作れない人が、自動で発注する装置を作るべきではありません。

C は最後です。3 本のうち唯一、失敗が金銭で精算されるからです。

いま優先すべき技術課題は 1 つ

3 本すべての土台として、抽出失敗の修復が最優先です。 難問では gpt-oss-120b の 78%、deepseek-v4-pro の 67% が無効発火しており、 「4 系統で投票している」という前提が成り立っていません。 実際、Fable 超えを阻んだ直接の原因もこれでした—— 検証プログラムが正解を計算していたのに、他の 2 本が空応答で、合意規則がそれを棄却しました。

新しい集約理論を足すより、素子が確実に発火するようにするほうが、 3 本すべてに効きます。
