この比喩が破れる 3 点

① 重みが学習されていない。 素子間の結合強度にあたるものは SC_MIN_VOTES=3、SC_COURT_MARGIN=2.0、SC_MAX=20 といった 手書きの定数です。つまりこれは訓練されたネットワークではなく、 重みを人手で置いた計算グラフです。

② エッジがベクトルではなくテキスト。 シナプスは実数倍ではなくプロンプトテンプレートです。 情報は圧縮されず、そのぶん劣化もしませんが、代わりに次元という概念がありません。

③ 発火コストが桁違い。 1 ニューロンの 1 回の発火が API 呼び出し 1 回＝数秒〜数分。 生物ニューロンでもニューラルネットでもなく、1 素子が組織の 1 人に近いスケールです。

理由はコードのコメントに書かれています。

sc6 実測の核心: 全 38 サンプル中に正解が一度も生成されない問題は集約では救えない

集約は「生成された候補の中から選ぶ」操作です。正解が候補集合に一度も現れなければ、 多数決も対審も自信度加重も、原理的に救えません。 ニューラルネットの言葉なら、出力は隠れ層の張る空間に閉じ込められている、ということです。

相関したユニットで層を広げても、実効的な容量は増えません。 32 個のユニットがほぼ同じ関数を計算しているなら、実効ランクは 32 ではなく数個です。 温度サンプリングは同じ重みのユニットにノイズを足しているだけなので、 原理的に新しい基底を張れません。

S3C（戦略層化）がやったのは、ユニットごとに異なる基底を強制的に割り当てることです。 実装はプロンプトへの 1 行注入にすぎません。

Implications

この見方が示す次の一手

回路として眺めると、まだ手を付けていない構造がいくつか見えます。

1. ゲートが 1 層しかなく、しかも一度しか発火しない

Conductor は入口で 1 回だけ動き、以降の経路は固定されます。 通常のネットワークなら、各層に独立したゲートが入ります。 「投票が割れたときに、どの素子を追加で発火させるか」を選ぶ第 2 のゲートは存在せず、 現状は全系統から均等に追加サンプリングしています。ここは疎化の余地があります。

2. スキップ結合がない

入力 x は Conductor と提案素子には届きますが、集約層や検証層には直接届いていません。 Aggregator は提案文だけを見て統合し、判事は候補と問題文を見ます。 深いネットワークで残差結合が効くのと同じ理由で、 元の問題文を後段の全層へ直結させる価値はありそうです。

3. 唯一の外部オラクル（PoT）が 1 経路にしか繋がっていない

Python 実行は SC 経路にしか配線されていません。MoA 経路（コード生成・設計・説明）には繋がっていない。 系全体で唯一の決定的な素子が、半分の経路でしか使われていないのは、 回路図にすると不自然に見えます。

4. 重みが手書きである以上、律速はそこにある

学習が存在しない以上、この回路の性能を決めているのは SC_MIN_VOTES・SC_COURT_MARGIN・SC_MAX といった定数と、 正解判定を行う採点器です。ネットワークの外側に、人手で置かれた重みがある。 「ボトルネックはモデルではなく報酬シグナル」という以前の結論は、 この図では「重みが学習されていないこと」として現れます。

2026-08-06 追記 — 上の 2 と 3 は実装して測りました

2（スキップ結合）と 3（外部オラクルの配線）は、統合 MoA（u@nim）として 実装済みです。原問題を全層へ直結する残差結合を入れ、検証層（実行検証・Critic・第二意見）を 全経路へ配線しました。ついでに 1 の「ゲートが 1 層しかない」問題も、 経路分岐そのものを廃止して出力の性質で集約方式を決める方式に置き換えています。

結果は精度で既存を上回りませんでした——MATH-500 の 42 問で 既存 42/42 に対し 41/42、リクエストは 1 問あたり約 7 倍。 回帰した問題はいずれも早期確定で軽く終わって誤答しており、 回路を深くする前に、素子の発火失敗（抽出失敗）を直すほうが先だった というのが実測から出た答えです。

この図の言葉で言えば——ユニットの 2/3 が発火に失敗している層で、 配線を増やしても出力は良くならない。 gpt-oss-120b は失敗寄り問題集合で 78%、deepseek-v4-pro は 67% が無効発火でした。 4 素子で投票しているつもりが、実際には 2 素子で回っていたことになります。 詳細はトップページの発見セクションにあります。
