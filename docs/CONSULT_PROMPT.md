## ここからコピー

私は個人開発で、複数の LLM を組み合わせて動く推論オーケストレータを作っています。
これから述べる設計案について、**賛成・反対のどちらでも構わないので、根拠を示して評価してください。**
私はこの案に愛着があるので、**欠点や「そもそも筋が悪い」という指摘こそ知りたい**です。
一般論ではなく、下の実測値と制約に即して答えてください。

### 1. 現在のシステム（事実のみ）

複数のオープンウェイト LLM（クラウド API 経由・無料枠）を束ねるオーケストレータです。
入口で軽量モデルが「どのモデルをどう使うか」を判断し、複数モデルの並列生成 →
統合または多数決 → 批評・再試行、という流れで答えを出します。

実測値（6 種目 210 問・自作ハーネスによる自己採点）:

- 総合 199/210。同一ハーネスで測った商用フロンティアモデル 1 種は 199.5/210
- 同じモデル群を **単発で呼ぶと約 40%、オーケストレーションに通すと 97%**（数学競技問題 30 問）
- 外部課金 0 円。4 日間で累計 16,506 リクエスト、無人稼働
- **1 問あたり中央値 5.3 分・最長 35 分**
- 難問では、モデルによって出力から答えを抽出できない割合が高い
  （あるモデルは 78%、別のモデルは 67% が無効。実質 4 系統中 2 系統しか機能していない）
- 「推論を段に分解して段ごとに投票する」改修を実装して測ったところ、
  精度は既存と同等〜わずかに下、コストは約 7 倍だった
- 生成トークンの確信度で票を重み付けする既存手法を実装したところ、
  異種モデル混成では有害だった（正解の多数派を少数派の誤答に上書きした）

技術的制約:

- クラウド側のモデルは API 経由のみで、**重みは入手できない**
- ローカル実行環境は GPU 8GB / RAM 48GB / 空きディスク 750GB
- 本体は Python 標準ライブラリのみで動作。会話履歴の永続化と自作 RAG は実装済み
- 入口の判定器（どの経路を使うか決める部分）と各種しきい値は、**すべて手書きの定数**で、
  学習されていない

### 2. 想定している用途

1. 日常使いの対話（調べもの・下書き・要約）
2. 自律的なコーディング（実装 → テスト → 測定 → 改善のループ）
3. 金融バックテスト（戦略の探索と検証）
4. 現時点で思いついていない用途が他にもあると考えている

### 3. 相談したい設計案

**「1 つの用途＝1 つのニューロン」と見なし、用途ニューロンの配置を
ニューラルネットのアーキテクチャ（Transformer / Mamba / その他）と同じ構図で設計する。
開発者が要望を入力すると、それらのニューロンを通って推論が進み、
全体として 1 つのモデル（＝システム）になる。」**

補足として私が現時点で考えていること:

- モデルマージや蒸留も候補だが、**それらは最後の段階**だと考えている
- まず各用途をニューロンとして表現し、合成することが先だと考えている

### 4. 聞きたいこと

以下について、**それぞれ賛否と根拠を**述べてください。

1. **この「用途＝ニューロン」という抽象化は妥当ですか。**
   有効な設計指針になりますか、それとも図解上の比喩に留まり実装判断を助けませんか。
   もし後者なら、代わりに何を設計の中心に置くべきですか。

2. **もし何らかのアーキテクチャに似せるとしたら、どれが適切ですか。**
   Transformer / Mamba(SSM) / MoE / その他 / **どれにも似せるべきでない**、
   のいずれかを選び、理由を述べてください。
   特に「用途が 3〜5 個しかない」規模で、その選択に意味があるかを論じてください。

3. **重みが学習されていないことは、この構想にとって致命的ですか。**
   学習可能にすべきなら、何を、どのデータで、どう学習させますか。
   学習不要なら、なぜ不要ですか。

4. **マージ・蒸留を最後に回すという順序は正しいですか。**
   逆順（先に 1 体に畳み込んでから機能を足す）のほうが良い可能性はありますか。

5. **上の実測値のうち、この設計案にとって最も不都合な事実はどれですか。**
   その事実は案を修正すれば回避できますか、それとも案そのものを棄却すべき根拠ですか。

6. **私がまだ考慮していない選択肢があれば挙げてください。**
   「そもそもこの方向に進むべきでない」という結論も歓迎します。

### 5. 回答時のお願い

- 私の案を褒める必要はありません。**弱点の指摘を優先してください**
- 抽象論ではなく、上の数値（5.3 分、78%/67% の抽出失敗、7 倍のコスト増、8GB GPU など）
  に紐づけて論じてください
- 「やってみないと分からない」で終える場合は、**何を測れば決着するのか**を具体的に示してください
- 実装の詳細より、**判断の分かれ目**を明確にしてください
