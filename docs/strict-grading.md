## 採点を4段階に分解する

| 段階 | 判定 |
|---|---|
| `exact` | `got` と `expected` が文字列として完全一致 |
| `normalized` | `normalize_answer()` を通すと一致（表記ゆれの救済） |
| `equivalent` | さらに `Fraction` / `math_verify` で数学的に同値 |
| `wrong` | どれでも一致しない |

**厳密採点 = `exact` のみ。寛容採点 = `equivalent` まで許す（現行）。**
fugu と Fable を同じ手続きで採点し、**IDの積集合**だけで比較する。

> `test_geometry_880.json`（期待 `2\sqrt{113}` / 出力 `4\sqrt{29}`）は結果ファイルに
> `correct=False` で記録されている。つまり寛容採点でも誤答として数えられており、

> **等価判定の段でしか通っていない答えを 1 問ずつ目で見て**確かめた結果である。

## 対処: `fugu_canonical.canonicalize_math_answer()`

**採点器は触っていない。**直したのは出力側である。

- `expected` を一切見ない（引数は自分の出力だけ。テストでシグネチャを固定）
- 値を変えない。表記だけを揃える
- 投票そのものには手を入れていない。**票は値について、報告は形式についてであり別の話**

変換するもの: `\dfrac`/`\tfrac` → `\frac` ／ `a/b` → `\frac{a}{b}` ／
`sqrt(x)` → `\sqrt{x}` ／ 有限小数 → 既約分数。

変換しないもの（誤変換の危険が大きい）: 度記号の付与・桁区切り・選択肢の `\text{}` 化・空白の増減。

### 効果（記録済みデータで実測）

**8問を救済。math500 の厳密が 32/50 → 40/50、fugu 全体で 182 → 190。**
Fable の 191 まであと1問。

## 残りをどこまで詰められるか

### 原理的に取れないものがある

**参照解答（MATH-500）側の表記が統一されていない。**

- `\frac{...}` を使う問題と `\dfrac{17}{50}` を使う問題が混在している
- `-13x+3`（空白なし）と `288 \pi`（空白あり）が混在している

したがって**厳密完全一致で満点を狙うのは不可能**であり、
現実的な目標は「Fable と同等」であって「全問一致」ではない。

> **残り 1 問（空白）を詰めるべきかを測った（2026-08-27）— 結論: 詰めない。**
>
> canonicalize 後に残る差はちょうど 1 問、`test_intermediate_algebra_1210.json`
> （期待 `-13x+3` / 出力 `-13x + 3`）だけである。「英字を含む式では `+ - =` の周りの
> 空白を詰める」という規則を足せば 191/191 の同点に届く。08-21..23 と 08-08 の
> 2 走行で試すと、どちらも回帰 0 で通る。
>
> **しかしこれは 50 問の標本への過適合である。**MATH-500 の参照解答 500 件全体で
> 「英字を含み、演算子の周りに空白がある／ない」を数えると:
>
> | | 件数 | 例 |
> |---|---:|---|
> | 空白**あり** | **12** | `x^5 - x^4 + x^3 - x^2 + x - 1` / `y = 2x + 3` / `6 - 5i` |
> | 空白**なし** | **12** | `-13x+3` ほか |
>
> **12 対 12。規約は存在しない。**この規則は今回測った 50 問では 1 問得をしたが、
> 母集団に対しては表が出るか裏が出るかであり、詰めた側で落ちる問題を同じだけ生む。
> **「測った標本で回帰 0」は、規則が正しいことの証拠にはならない。**
>
> よって空白詰めは実装しない。厳密採点の到達点は **190 対 191（-1）**のままとする。
> この -1 は fugu の弱点ではなく、**参照解答側に表記規約が無いことの現れ**である。

### プロンプト側で取れる見込みのもの（未検証）

度記号3問・変数宣言1問・選択肢書式1問は、
「問われた形式のまま答える」よう指示すれば取れる可能性がある（**+3〜5問の見込み**）。
ただし**これは再計測しないと確認できない**。本監査では実装していない。
